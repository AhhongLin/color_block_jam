# Color Block Jam 網頁版 — 規格文件

> 本文件是 [Color Block Jam 網頁版規格地圖](map.md) 的交付產物，彙整地圖上六個 ticket 的決策結論。地圖本身保留決策的討論脈絡與連結；本文件是給實作階段（`/implement` 或 `/tdd`）直接讀的規格。

## 1. 遊戲概述

一款瀏覽器版的顏色方塊推箱子解謎遊戲（Color Block Jam 類型）：玩家在不規則形狀的盤面上，拖曳方塊沿上下左右其中一個方向滑動，方塊會持續滑動直到撞到牆壁或其他方塊為止；當方塊的前緣完全對齊盤面邊界上的同色門，方塊會滑出盤面消失。清空盤面上所有方塊即過關。

**MVP 範圍**：核心滑動玩法、任意形狀方塊、任意不規則盤面、簡單關卡選單與進度儲存。**不包含**原版手機遊戲的箭頭方塊、冰凍方塊、計時器、生命值、金幣/道具、廣告續命、關卡編輯器（見第 9 節「範圍外」）。

## 2. 核心玩法規則

### 2.1 觸發與操作

- 玩家在方塊上用拖曳手勢（滑鼠拖曳或觸控拖曳，統一透過瀏覽器 [Pointer Events](https://developer.mozilla.org/docs/Web/API/Pointer_events) 處理）指定滑動方向：上、下、左、右四個方向之一。
- 不支援「點選方塊 + 點方向鍵」等替代操作，MVP 只做拖曳。

### 2.2 滑動與碰撞

- 方塊沿拖曳方向即時跟著滑鼠／手指移動（拖曳中就會動，不必等放開）；放開時停在放開當下最接近的那一格。玩家可以選擇只滑一部分或滑到底，但最遠不會超過遇到障礙物（盤面邊界的非門格、或其他方塊）前的最後一格——也就是說，可行範圍永遠受碰撞限制，只是「滑多遠」改由玩家的拖曳距離決定，不是固定滑到底。
- **不推動**：滑動中的方塊撞到別的方塊時，只會停下，不會推動對方（無連鎖推箱子行為）。
- **多格方塊碰撞判定**：方塊可以是任意多格子拼接的形狀（1x1、2x1、L 形等），用一組格子座標定義。碰撞判定採「逐格模擬」：每一步把整個形狀的所有格子往指定方向移動一格，檢查移動後的所有新格子是否都落在盤面內且未被其他方塊佔用；可行就繼續下一步，不可行就停在上一步的位置。

### 2.3 盤面與門

- 盤面可以是任意不規則形狀（允許挖洞、不規則邊界），不限定為完整矩形。
- 門位於盤面的邊界格子上，每個門有指定的方向（朝外）與顏色。
- 同一種顏色允許有多個門，方塊只要顏色相符，可以從任一個同色門離開。

### 2.4 離場（過門）

- 方塊滑到邊界時，若其**前緣的所有格子**都對齊同色門格，整個方塊才會一次滑出盤面並消失。
- 只要前緣有任一格沒有對齊同色門（門顏色不符、或該邊界格根本不是門），該方塊視同撞牆，停在邊界前面，不會部分離場。

> **實作階段更新（離場判定跟移動方向脫鉤）**：離場判定只看方塊「目前的位置」有沒有貼齊同色門，不限定是剛剛那一步滑動的方向。例如方塊先往右滑一格對齊右側門柱，下一步往下滑到底，只要下側也同時貼齊同色門，即使玩家這步是往下滑，也照樣離場——不需要玩家額外再往右滑一次來「觸發」右側門。每次移動後會依序檢查上下左右四個方向，只要有任一方向的前緣對齊同色門就離場（見 `src/game/exit.ts` 的 `findExitDirection()`）。

### 2.5 過關與失敗處理

- 盤面上所有方塊都離場即過關。
- **MVP 不做死局偵測**：不主動判斷盤面是否已無解。玩家卡關時，UI 提供一顆「重設關卡」按鈕，讓方塊回到關卡初始位置重新挑戰。

## 3. 資料模型（Level JSON Schema，第一版）

關卡資料是手工撰寫的 JSON 檔，不做關卡編輯器工具。以下是依上述規則推導出的第一版 schema，供實作時參考、可視需要微調：

```ts
type Color = "red" | "blue" | "green" | "yellow"; // 可擴充

interface Level {
  id: string;                    // 例如 "level-01"
  name: string;                  // 顯示用關卡名稱
  cells: [number, number][];     // 盤面上所有「地板」格子的座標 [row, col]
  doors: {
    row: number;
    col: number;                 // 必須是 cells 邊界上的格子
    side: "top" | "right" | "bottom" | "left"; // 門朝外的方向
    color: Color;
  }[];
  blocks: {
    id: string;
    color: Color;
    cells: [number, number][];   // 該方塊佔用的格子座標，定義任意形狀
  }[];
}
```

- `cells` 定義盤面的可行走範圍（等同「地板」格），未列出的座標視為盤面外/挖洞。
- 碰撞與離場判定（見 2.2、2.4）皆以此 schema 的座標系統為準。

## 4. 視覺設計

已用 `/prototype` 做過三版低保真比較（原型碼保留在 throwaway 分支 `prototype/visual-style`，commit `249a4a9`，不進 main），選定 **Variant B「圓潤活潑」**：

### 4.1 風格基調

- 大圓角、底部實色陰影營造立體感。
- 方塊被選中/拖曳時放大約 6% 並加上白色外框光暈。
- 盤面格：白色半透明、圓角，背景為暖色系漸層（米黃 → 粉）。
- 門：圓角膠囊造型，帶同色 glow 光暈。

> **實作階段更新（方塊材質）**：另用 `/prototype` 比較過三種方塊「材質」處理法（`.scratch/color-block-jam-web/block-style-prototype.html`，throwaway 原型檔，未進路由），選定 **Variant A「糖果光澤」**取代原本的雙色漸層填色：方塊改為單一 `--block-color` 平色 + 多層 `inset` box-shadow 疊出立體邊緣、左上角疊一層放射狀白色高光模擬玻璃反光。下方色票同步更新為單一實色（原本的雙色漸層僅供 box-shadow 的 `color-mix()` 提亮/加深使用，不再是填色本身）。

### 4.2 參考色票（取自原型，實作時可微調對比度/色盲友善度）

| 顏色 | 實色（`--block-color`） |
|---|---|
| red | `#e6453f` |
| blue | `#3b6fe0` |
| green | `#2fae66` |
| yellow | `#e6b800` |

### 4.3 關卡選單

- 路徑地圖風格（類似 Candy Crush 的世界地圖），圓形關卡節點沿蜿蜒路徑排列。
- 已完成關卡顯示星級評分；未解鎖關卡呈灰階、不可點擊。

## 5. 音效

- MVP **只做互動音效，不做背景音樂**（背景音樂涉及選曲/循環播放/靜音開關，留給之後擴充）。
- 播放時機僅限：
  1. 方塊離場（滑出同色門）
  2. 過關完成
- 素材來源：免費音效庫（如 [freesound.org](https://freesound.org)）挑選 CC 授權短音效，下載後放進專案的 assets 資料夾，需標註授權條款。

## 6. 關卡設計

- MVP 手工設計 **8 關**，難度曲線採線性遞進：
  - **第 1-2 關**：純教學，單一機制，少量 1x1/2x1 方塊，規則矩形盤面。
  - **第 3-5 關**：加入 L 形等多格方塊、不規則盤面形狀。
  - **第 6-8 關**：方塊數量與盤面複雜度提高，需要多步規劃。
- 不做額外的教學提示 UI（引導圖層、手勢動畫提示等），靠關卡設計本身教會玩家——例如第 1 關就是最簡單的單一方塊 + 單一同色門。

## 7. 裝置與響應式支援

- 桌面與行動裝置皆需支援，拖曳輸入統一透過 Pointer Events 處理（滑鼠拖曳與觸控拖曳共用同一套邏輯）。
- 需要 RWD：從手機直向到桌面寬螢幕都要能正常遊玩，盤面格子尺寸依可視寬度等比例縮放，關卡選單與其他 UI 元素在不同寬度下都要維持可用性。

## 8. 技術架構

| 項目 | 選擇 |
|---|---|
| 建置工具 | Vite |
| 框架 | React 18 |
| 語言 | TypeScript |
| 狀態管理 | React 內建 `useState` / `useReducer`（不引入 Zustand/Redux） |
| 樣式 | CSS Modules |
| 動畫 | CSS transition（`transform` 做方塊滑動位移） |
| 路由 | React Router 的 `BrowserRouter`，每一關/每個畫面都有自己的 URL（如 `/level/3`） |
| 進度儲存 | `localStorage`（無後端、無資料庫） |

**測試策略**：核心遊戲邏輯（滑動、碰撞、過關判定）用 `/tdd` 開發（單元測試驗證純邏輯，與 UI 分離）。

## 9. 部署與瀏覽器支援

- **瀏覽器支援**：僅現代瀏覽器（evergreen：最新兩個大版本的 Chrome/Edge/Firefox/Safari），不考慮 IE 或舊版相容，不需額外 polyfill。
- **部署平台**：GitHub Pages。
- **SPA routing 處理**：`BrowserRouter` 搭配 GitHub Pages 的 `404.html` 重定向 trick 模擬 SPA fallback；`vite.config` 需設定對應的 `base` path（對齊 repo 名稱）。

## 10. 範圍外（Out of scope）

以下原版機制明確排除於此次網頁版 MVP 之外：

- 箭頭方塊、冰凍方塊、計時器、生命值、金幣/道具、廣告續命
- 關卡編輯器 UI（MVP 用手工 JSON 關卡檔）
